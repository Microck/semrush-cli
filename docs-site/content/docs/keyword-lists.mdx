---
title: Keyword lists
description: Manage Keyword Strategy Builder lists, keywords, tags and clustering.
---

These commands use the Keyword Strategy Builder API. Use `BasketID` and
`Owner.ID` from `keyword-lists` when selecting a basket. Regular collections
can also appear in Saved Keywords with the same underlying ID; that API uses
decimal-string `list_id` fields. Project folder IDs remain a different identifier. Shared
lists retain their owner's ID. Semrush enforces the list's access permissions.

## Domain-based strategies

The domain-based workflow uses a separate strategy resource. It does not create
a seed-based basket or project. Creation starts generation and uses your normal
account allowance.

```sh
semrush domain-strategies --limit 20 --offset 0 --json
semrush domain-strategy-summary --json
semrush domain-strategy-create --domain example.com --database us --dry-run
semrush domain-strategy-create --domain example.com --database us --confirm --json
```

Creation returns `data.id`. Use that numeric ID for these commands:

```sh
semrush domain-strategy-get --strategy-id 123 --json
semrush domain-strategy-status --strategy-ids '[123]' --json
semrush domain-strategy-rename --strategy-id 123 --name 'domain research' --confirm
semrush domain-strategies --name-filter 'domain research' --ownership own --json
semrush domain-strategy-delete --strategy-ids '[123]' --confirm
```

Status reads return a `statuses` array in the requested ID order. Inspect details
for the domain, state, result availability and page count. Read status again
explicitly while generation runs. No command retries writes or polls
automatically. Delete has no CLI undo command.

Domain strategy IDs must be safe JSON integers. They are not project folder IDs
or a basket selector. Basket operations below use both `BasketID` and `Owner.ID`.
Geographic-marker search from the client is unavailable on the current backend;
the CLI does not expose those dormant methods.

## Read domain opportunities and export

Wait until generation has results before reading page opportunities. Presets
are `all`, `improve` and `create`. Page results use `data.pages`; each page has
its own numeric `id`, distinct from the strategy ID.

```sh
semrush domain-strategy-presets --strategy-id 123 --json
semrush domain-strategy-pages --strategy-id 123 --preset improve --limit 20 --offset 0 --json
semrush domain-strategy-pages-summary --strategy-id 123 --preset improve --json
semrush domain-strategy-page --page-id 456 --json
semrush domain-strategy-page-urls --page-id 456 --json
semrush domain-strategy-page-serp --page-id 456 --json
semrush domain-strategy-existing-keywords --page-id 456 --json
semrush domain-strategy-recommended-keywords --page-id 456 --json
```

Page reads and summaries accept `--text`, `--volume-min`, `--volume-max`,
`--difficulty-min`, `--difficulty-max` and `--primary-intents`. Pass intents
as a JSON array, such as `'["commercial","transactional"]'`. Supported values
are `informational`, `navigational`, `commercial` and `transactional`. Difficulty
ranges from 0 to 100. Minimum bounds cannot exceed maximum bounds. Advance
`--offset` explicitly to read later pages.

Delete only selected numeric keyword IDs returned by the keyword reads:

```sh
semrush domain-strategy-keywords-delete --keyword-ids '[789]' --dry-run
semrush domain-strategy-keywords-delete --keyword-ids '[789]' --confirm
semrush domain-strategy-export --strategy-id 123 --filename research --format csv --output research.csv
semrush domain-strategy-export --strategy-id 123 --filename research --format xlsx --output research.xlsx
```

Keyword deletion has no CLI undo command. Export supports `csv`,
`csv_semicolon` and `xlsx`, plus the same text, volume, difficulty and intent
filters. It exports the whole filtered strategy and does not accept a preset.
`--output` is required. An existing destination is preserved; choose a new
path to save another export. MCP returns a downloadable resource instead of a
local path. See [MCP exports](/docs/mcp#read-an-export).

## Create and manage lists

```sh
semrush keyword-list-limits --json
semrush keyword-lists --page 1 --page-size 100 --json
semrush keyword-list-create --name 'research' --dry-run
semrush keyword-list-create --name 'research' --confirm --json
semrush keyword-list-get --basket-id 456 --owner-id 123 --json
semrush keyword-list-rename --basket-id 456 --owner-id 123 --name 'new name' --confirm
```

Regular list creation adds an empty list. It does not start strategy generation
or clustering. List reads support a name filter, ownership bitmask, pagination
and sorting. The default ownership value `7` includes owned and shared lists.
`keyword-list-delete --basket-id 456 --confirm` permanently deletes one of your
lists. The MCP tool carries a destructive annotation.

Every write requires `--confirm`, or MCP `confirm:true`. Use `--dry-run` or
`dry_run:true` to inspect the request before authentication. RPC previews omit
runtime credentials. No command accepts API keys or arbitrary RPC methods.

## Keywords and tags

```sh
semrush keyword-list-import --basket-id 456 --owner-id 123 --keywords '["email marketing","seo"]' --database us --confirm
semrush keyword-list-keywords --basket-id 456 --owner-id 123 --page 1 --page-size 20 --json
semrush keyword-list-summary --basket-id 456 --owner-id 123 --json
semrush keyword-list-add-tags --basket-id 456 --owner-id 123 --keywords '["seo"]' --tags '["opportunity"]' --confirm
semrush keyword-list-tags --basket-id 456 --owner-id 123 --json
semrush keyword-list-remove-tags --basket-id 456 --owner-id 123 --keywords '["seo"]' --tags '["opportunity"]' --confirm
```

Keyword selections use a JSON array of phrases and a database flag. Import can
also attach a common tag array with `--tags`. Account keyword limits apply.
Keyword reads support pagination, sorting and the web API's `--filters` object.
Omitted filter fields become empty arrays. Available fields are `ClusterIDs`,
`Databases`, `Phrase`, `CompetitionLevel`, `Cpc`, `Difficulty`, `SERPFeatures`,
`Volume`, `ClickPotential`, `Tags` and `Intents`.

To remove phrases, use `keyword-list-delete-keywords` with the same selection
flags and `--confirm`. It returns an `UndoID`. Restore that deletion with
`keyword-list-undo-delete --undo-id <UndoID> --confirm`. Restoration uses the
current account's permissions and the provider's undo lifetime.

## Generation and metric refresh

```sh
semrush keyword-strategy-create --name 'example strategy' --domain example.com --dry-run
semrush keyword-strategy-create --name 'topic strategy' --seed-keywords '["email marketing"]' --database us --confirm
semrush keyword-list-update-metrics --basket-id 456 --owner-id 123 --keywords '["seo"]' --confirm
semrush keyword-list-cluster --basket-id 456 --owner-id 123 --confirm
semrush keyword-list-cluster-status --basket-id 456 --owner-id 123 --json
```

Strategy generation accepts a domain, seed phrases, or both, plus optional
competitors and database selection. It creates a structured list and consumes
the clustering allowance. Metric refresh consumes the update allowance. These
operations are asynchronous. `keyword-list-cluster-forecast` reads the seed
forecast of a structured strategy; a plain manual list has no generation
forecast and returns a provider error. Use the strategy basket ID returned by
`keyword-strategy-create` for that read. Read their status or refreshed data explicitly;
the CLI does not retry writes or poll automatically.

List IDs and owner IDs must be exact JSON integers within JavaScript's safe
integer range. The input schema rejects larger numbers rather than rounding.
Project folder IDs keep their separate decimal-string representation.
