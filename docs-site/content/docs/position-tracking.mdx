---
title: Position Tracking
description: Create tracking targets, manage keywords and read rankings.
---

Enable SEO on a project before creating a tracking target. The numeric SEO
project ID differs from both the project folder ID and a tracking campaign ID.
Read `position-limits` before creating targets or adding keywords.

```sh
semrush position-locations --query 'United States'
semrush position-limits --project-id 456
semrush position-targets --project-id 456
```

## Create a target

```sh
semrush position-create \
  --project-id 456 --domain example.com \
  --keywords '["example domain"]' --location-id 2840 --dry-run

semrush position-create \
  --project-id 456 --domain example.com \
  --keywords '["example domain"]' --location-id 2840 --confirm
```

Creation starts tracking and consumes target and keyword allowances. Defaults
are Google, desktop, English, national search volume, UTC and no weekly emails.
Find supported options with `position-create --help`. The returned campaign ID
has two numeric parts, such as `456_789`. Keep that complete string for reads
and writes. Do not substitute the project ID alone.

## Manage keywords and competitors

```sh
semrush position-keywords-add --campaign-id 456_789 \
  --keywords '["example website"]' --tags '["research"]' --confirm

semrush position-keyword-tags --campaign-id 456_789 \
  --keywords '["example website"]' --add-tags '["reviewed"]' \
  --remove-tags '["research"]' --confirm

semrush position-competitors-set --campaign-id 456_789 \
  --competitors '["example.org"]' --confirm

semrush position-keywords-delete --campaign-id 456_789 \
  --keywords '["example website"]' --confirm
```

Competitor replacement sets the complete competitor list. An empty JSON array
clears it. Keyword deletion removes those phrases from tracking. Writes also
support `--dry-run`, which validates and prints the request without signing in.

## Change tracked address and business settings

Settings edits preserve fields you omit. Changing the tracked address requires
both `--domain` and `--url-type`. Supported types are `rootdomain`, `subdomain`,
`subfolder` and `url`.

```sh
semrush position-configure --campaign-id 456_789 --business-name 'example business' --dry-run
semrush position-configure --campaign-id 456_789 --business-name 'example business' --confirm
semrush position-configure --campaign-id 456_789 --business-name '' --confirm
semrush position-configure --campaign-id 456_789 --brands '["example"]' --confirm
semrush position-configure --campaign-id 456_789 --domain docs.example.com --url-type subdomain --confirm
semrush position-configure --campaign-id 456_789 --volume-type national --confirm
```

An empty business name clears that field. Brands must be a nonempty array.
The current provider accepts an empty brand array but retains the old values,
so the CLI rejects that request. Brand-list clearing remains unsupported.

The browser reads current settings and fresh edit metadata before submitting
the native request. Internal edit tokens never appear in previews or results.
This command does not replace the search engine, device, language or location.

## Manage alert rules

List alerts without marking them as read, or inspect existing rules and counts:

```sh
semrush position-alerts --campaign-id 456_789 --page 1 --limit 50
semrush position-alert-counts --campaign-id 456_789
semrush position-triggers --campaign-id 456_789
semrush position-trigger-count --campaign-id 456_789
```

Alert pagination starts at page 1, with at most 50 rows per page. Responses keep
native timestamps and the provider's `error_code` envelope. A nonzero error code
fails even when the provider returns HTTP 200.

Use the exact ASCII `data.campaign_settings.tracking_url` or competitor URL
from `position-info` for a rule's `--domain`. This value is separate from the
wildcard patterns used in ranking reports below.

```sh
semrush position-trigger-create --campaign-id 456_789 --domain example.com --condition enters_top --threshold 10 --dry-run
semrush position-trigger-create --campaign-id 456_789 --domain example.com --condition enters_top --threshold 10 --confirm
semrush position-trigger-update --campaign-id 456_789 --trigger-id opaque-rule-id --domain example.com --condition leaves_top --threshold 20 --confirm
semrush position-trigger-delete --campaign-id 456_789 --trigger-id opaque-rule-id --confirm
```

Creation returns a string `trigger_id`; use it without numeric conversion.
Update replaces the rule, so supply its domain, condition and threshold again.
Conditions are `enters_top`, `leaves_top`, `changes_more_than`, `gains_more_than`
and `loses_more_than`. Thresholds are integers from 1 to 100. Rules apply to all
tracked keywords and the position metric. Semrush enforces rule limits.

These commands do not enable weekly emails or schedule email exports. The native
alert-detail action also marks an alert as read, so it is not exposed as a
read-only command. Alert-event changes remain web-only.

## Read rankings

```sh
semrush position-info --campaign-id 456_789
semrush position-tags --campaign-id 456_789
semrush position-campaign-limits --campaign-id 456_789
```

`position-info` returns available dates, campaign settings and competitors.
Choose `date_begin` and `date_end` within `data.dates.min` and `data.dates.max`.
Dates use YYYYMMDD. New targets need time to collect rankings.

```sh
semrush position-overview --campaign-id 456_789 \
  --date-begin 20261015 --date-end 20261015 \
  --competitors '["*.example.com/*"]' --limit 20 --offset 0
```

Use the same dates and competitor target patterns with
`position-overview-trend`, `position-distribution-trend`, `position-pages` and
`position-cannibalization-trend`. A root-domain pattern includes subdomains and
paths. Quote the JSON array so the shell does not expand its wildcard characters.

Responses preserve the provider's native `status` and `data` envelope. The
rankings report's `data.keywords` contains tracked phrases, tags, positions and
landing URLs. `data.total`, `limit` and `offset` support pagination.
