## Find a template

```sh
semrush reporting-overview --json > reporting.json
jq '.data.systemTemplates[] | {type, title, isPremium}' reporting.json
```

The result includes your reporting actions, allowances and saved reports.
My Reports has its own product settings. Its `isPaid` field does not describe
your SEO subscription.

## Create a report

Use a template type from the overview and the parameters that template needs.
This example creates an Organic Search Positions report without generating a PDF:

```sh
semrush reporting-create \
  --template tc_organic_search_positions \
  --parameters '{"domain":"example.com","database":"us"}' \
  --confirm --json
```

The saved report ID is in `data.userDocumentId`. Use that ID in later commands.
Templates that need connected services or a different reporting tier require
that access in your Semrush account.

## Edit a saved report

Read the complete document, change the fields you need and save the full object:

```sh
semrush reporting-get --report-id 123 --json > report.json
jq '.data.document | .name = "Monthly SEO"' report.json > document.json
semrush reporting-save --document-file document.json --confirm --json
```

Keep the document's `id`, populated `content` and other saved settings.
Saving replaces the submitted document and accepts the reporting Privacy Policy.
It does not generate a PDF. Review recipients and scheduling before saving or
generating a report.

To copy a report:

```sh
semrush reporting-clone --report-id 123 --name "Monthly SEO copy" --confirm --json
```

The new ID is in `data.document.id`.

## Generate and download a PDF

```sh
semrush reporting-generate --report-id 123 --confirm --json
semrush reporting-tasks --report-id 123 --json
```

Generation saves the current document and accepts the reporting Privacy Policy
before starting the native PDF task. It uses the report's saved delivery settings.
It can consume reporting allowance.

Find a task with `state: "ready"` in `data.reports.nodes[].tasks`, then use its
exact string ID:

```sh
semrush reporting-download --report-id 123 --task-id 456 --output monthly-seo.pdf
```

Downloading reads an existing PDF. It does not generate another report. The
output file must not already exist. MCP returns an artifact resource containing
the same PDF bytes. See [file resources](/docs/mcp#file-exports-and-resources).

## Find and delete reports

The overview returns up to 30 reports, newest update first. Keep filters the same
and increase `--offset` by 30 for each page:

```sh
semrush reporting-overview --ownership own --search "Monthly" --json
semrush reporting-overview --ownership own --search "Monthly" --offset 30 --json
```

Delete only the IDs you intend to remove. Deletion is permanent:

```sh
semrush reporting-delete --report-ids '[123,124]' --dry-run
semrush reporting-delete --report-ids '[123,124]' --confirm --json
```

Writes do not retry. If a response is lost, inspect the overview, saved document
or task list before sending another write.

See the [My Reports command reference](/docs/reference/reporting) for every option.
