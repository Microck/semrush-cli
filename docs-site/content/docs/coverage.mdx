## Verification

The source suite has 185 tests, including real Chromium, a private Galleton
daemon and stateful HTTP fixtures. All 48 original research mappings also have
differential tests against the Python reference. Across versioned live passes,
all 179 reads have execution evidence. The two latest Site Audit exports matched native CSV and XLSX downloads through MCP. The CLI markup XLSX matched workbook contents, with only the provider creation timestamp differing. The write checks combine native UI/API execution and real CLI/MCP calls; the versioned record identifies each pass. Shared-project leave
has request-contract coverage but no shared-account fixture.

Live checks covered project lifecycle, bounded Site Audit crawls and stop
controls, tracking targets and rankings, alert rules, saved keyword collections,
seed-based strategies and domain strategies. Native CSV/XLSX exports passed
file and resource checks. Tracking comparison returned positive desktop and
mobile ranks for the same phrase; pagination, sorting and intersection selectors
passed on owned targets.

Tracking replacement changed owned targets to mobile/Spanish and Bing/UK/English
while preserving keywords, tags and the checked settings. Single-target deletion
left the sibling intact. Location lookup now accepts a search engine because
Google and Bing use different numeric IDs. Replacement clears ranking history,
as the native wizard warns.

The notes pass verified all eleven operations. Partial edits preserved omitted
fields. Explicit project-scope and nonempty-link clearing, hide/show and category
replacement/restoration passed readbacks. MCP reconstructed the 2,781,804-byte
CSV in three chunks. CLI saving produced identical bytes and refused an existing
destination.

The protected-audit pass verified native multipart URL uploads, HTTP Basic
credential creation and replacement, retention across settings edits and
explicit disabling. A crawl capped at ten pages finished at six and returned
HTTP 200 for the protected HTML page from the uploaded list. Smaller two- and
five-page caps were consumed by discovery checks before reaching that page.
The upload filename is display metadata, not a sitemap URL.

The Backlink Audit pass returned a positive profile of 581 checked links. All
29 new reads and nondefault table filters passed live calls. Domain, individual
link and network moves passed destination reads and restoration checks. TXT
import/export and selected disavow move/delete passed real CLI/MCP calls;
file-source bulk clearing passed the native API. Partial settings edits preserved
omitted values, nonempty category/country selection passed, and explicit clearing
and restoration passed. See the [Backlink Audit guide](/docs/backlink-audit).

Earlier release passes deleted their owned fixtures and checked their absence.
The current import fixture is retained for scope-replacement verification.
Existing account resources were preserved. Credentials and detailed responses
stay outside the repository. [Versioned verification evidence](https://github.com/Microck/semrush-cli/blob/main/docs/verification.md)
records the tested releases and their public artifacts.

## Account and provider limits

The signed-in account's subscription page confirms **SEO Toolkit: Guru,
Subscribed**, alongside **Trial active**. The CLI and reference browser use
the same account. Trial status and generic billing flags do not identify the
SEO plan. The restrictions below describe responses observed with this
session; they do not imply that the CLI needs a different Guru account.

The verification account has no prompt-tracking allowance. The Advertising
Toolkit displays a paywall, and full paid-position research returned an access
denial. Those products are not verified as working.

The Position Tracking export menu says it requires a paid subscription. Its matching
request returned HTTP 403 with error code 1001, "action is not allowed". Tracking
exports remain unsupported. The native crawl-scheduling form requires SEO Tier
3. Guru subscription status alone does not verify access to that setting.

The Backlink Analytics export menu displays "Export is limited" and offers
"Upgrade to Guru" for this session. Its native client also checks trial status.
[Semrush documents CSV and Excel exports](https://www.semrush.com/kb/501-backlinks-report-manual),
and a bounded native CSV request returned HTTP 403 with the same Guru session.
These exports remain unsupported.

The Backlink Audit CSV button opens a trial-related subscription dialog, but
its native job API and download endpoint both accepted this Guru session. The
CLI supports native CSV and disavow TXT exports. The live MCP resource matched
the provider's CSV bytes exactly. UI trial flags alone do not establish access.

Backlink Audit scope replacement creates a new audit and discards the old analysis.
The native scope-only endpoint reset scheduling, so the CLI uses one native
creation request containing the saved settings. A completed root-to-both audit
retained nondefault brands, category, country and manual scheduling. Source MCP
replacement from both to nonwww retained explicit empty settings and disabled
notifications after analysis completed with 573 checked links. The old root
audit returned native 404.
The [audit guide](/docs/backlink-audit) explains the destructive behavior.

Position Tracking's general-settings endpoint retained old brands after an
empty-array write, so the CLI rejects it. The native Manage brand names editor
appears only for ChatGPT, Google AI Mode and Gemini targets. The prior Google
target probes do not verify that separate editor. A fresh owner-limit read
confirmed Guru with zero prompt allowance and `ai_seo_main:0`, so AI-target brand
matching and clearing remain unverified. Backlink Audit supports brand clearing.
Notes also have a native URL-validation quirk documented in the
[notes guide](/docs/notes). No subscription was purchased, outreach sent or
third-party service connected during verification.
