daemon and stateful HTTP fixtures. All 48 original research mappings also have
differential tests against the Python reference. Across versioned live passes,
229 previously released reads have execution evidence. Keyword Magic candidate
source verification is in progress for its three added reads and expanded
selection controls. The domain and AI

personalization and all 106 SERP rows. Preparation returned ready status 2
through both interfaces. Invalid-job status preserved native error -10401.
Pending jobs, lost replies and permission/quota failures have fixture evidence.

timestamps. SERP domain XLSX passed CLI and MCP file checks; separate export

release also passed national CLI and local MCP refresh/status checks. Lost receipts and

## Account and provider limits

The signed-in account's subscription page confirms **SEO Toolkit: Guru,
Subscribed**, alongside **Trial active**. The CLI and reference browser use
the same account. Trial status and generic billing flags do not identify the
SEO plan. The restrictions below describe responses observed with this
session; they do not imply that the CLI needs a different Guru account.

The native Keyword Strategy Builder Article sidebar offers a separate 7-day
Content Toolkit trial at $60/month when generation is submitted. Verification
did not activate it. Opening the sidebar itself can create a ContentShake
workspace for the selected project. The owned probe's empty workspace was
removed, and the original project folder remained available. The SEO brief
wizard opens, but its final generation and export are still unverified.
Content commands remain unsupported.

The verification account has no prompt-tracking allowance. The Advertising
Toolkit displays a paywall, and full paid-position research returned an access
denial. Those products are not verified as working.

The Position Tracking export menu says it requires a paid subscription. Its matching
request returned HTTP 403 with error code 1001, "action is not allowed". Tracking
exports remain unsupported. The native crawl-scheduling form requires SEO Tier
3. Guru subscription status alone does not verify access to that setting.

The Backlink Analytics export menu displays "Export is limited" and offers
"Upgrade to Guru" for this session. Its native client also checks trial status.
[Semrush documents CSV and Excel exports](https://www.semrush.com/kb/501-backlinks-report-manual),
and a bounded native CSV request returned HTTP 403 with the same Guru session.
These exports remain unsupported.

The Backlink Audit CSV button opens a trial-related subscription dialog, but
its native job API and download endpoint both accepted this Guru session. The
CLI supports native CSV and disavow TXT exports. The live MCP resource matched
the provider's CSV bytes exactly. UI trial flags alone do not establish access.

Backlink Audit scope replacement creates a new audit and discards the old analysis.
The native scope-only endpoint reset scheduling, so the CLI uses one native
creation request containing the saved settings. A completed root-to-both audit
retained nondefault brands, category, country and manual scheduling. Source MCP
replacement from both to nonwww retained explicit empty settings and disabled
notifications after analysis completed with 573 checked links. The old root
audit returned native 404.
The [audit guide](/docs/backlink-audit) explains the destructive behavior.

Position Tracking's general-settings endpoint retained old brands after an
empty-array write, so the CLI rejects it. The native Manage brand names editor
appears only for ChatGPT, Google AI Mode and Gemini targets. The prior Google
target probes do not verify that separate editor. A fresh owner-limit read
confirmed Guru with zero prompt allowance and `ai_seo_main:0`, so AI-target brand
matching and clearing remain unverified. Backlink Audit supports brand clearing.
Notes also have a native URL-validation quirk documented in the
[notes guide](/docs/notes). No subscription was purchased, outreach sent or
third-party service connected during verification.

The My Reports overview matched an independent native account query through
source and fresh public npm CLI and MCP. The Guru account returned Tier 2,
34 templates, zero saved reports and three Essential report slots. The native
constructor kept title
edits local; both saving and generation required a Privacy Policy acknowledgment.
Source and fresh npm CLI and MCP also matched nine native pagination and filter
selections. The live list was empty; real HTTP fixtures verify positive second
pages, page exhaustion and combined filters. See [My Reports](/docs/reporting)
for the read-only boundary.

The current Site Audit export menu does not offer a Crawled Links selection.
A links-download URL constant remains in its JavaScript bundle, but both CSV
and XLSX probes returned HTTP 404 with the same authenticated session. The CLI
does not expose that unverified route. Its current menu's page, issue, markup,
Compare Crawls and All reports downloads are supported.

## Native PDF access

Keyword Overview and Organic Research offer native Export to PDF controls.
They remain unsupported by the CLI. Inspection used the same authenticated
Guru session as the verified research commands.

Keyword Overview opened My Reports. Its native account metadata reported Tier 2,
three available Essential reports and an unaccepted privacy acknowledgment.
No report was created, privacy setting accepted or email sent. Organic Research
instead displayed an export limit and an upgrade prompt in that session. These
are distinct native access conditions; neither proves that the CLI used a
different account. Separate chart-image downloads were not verified.
