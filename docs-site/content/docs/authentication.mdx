## Visible sign-in

```sh
semrush setup
semrush auth login
semrush auth status --check --json
```

Sign-in requires a graphical desktop. The CLI waits up to five minutes. Enter your password only in the browser; Galleton stores the resulting session cookies, not your password. The CLI never logs cookies or page-owned API keys.

## Import an existing browser

Start a dedicated Chromium profile with a loopback debugging port, sign into Semrush, then import it:

```sh
semrush auth import --cdp-url http://127.0.0.1:9234
semrush doctor
```

The browser must already be running with CDP enabled. The reference `semrush-web-mcp` browser on port 9234 is supported. Import opens and closes one temporary page. It does not stop or reconfigure that browser. The URL must use HTTP and a literal loopback address such as `127.0.0.1`; public endpoints and hostnames are rejected.

For a remote signed-in browser, forward its loopback debugging port over SSH:

```sh
ssh -N -L 127.0.0.1:9234:127.0.0.1:9234 user@browser-host
```

Replace `user@browser-host` with your SSH destination. Leave the tunnel running
and run the import command above in another terminal. The local port must be
free. Keep the remote browser debugging port bound to loopback too.

Import verifies the account before storing cookies. Repeating import replaces only the selected CLI profile, using Galleton's revision check.

## Check the signed-in account

`semrush doctor --json` and `semrush auth status --check --json` include
`account.email` after an authenticated account report succeeds. A provider
response without an email produces null. These commands never infer an SEO
plan from generic billing flags. Check **Subscription info → SEO** in Semrush
for the actual toolkit subscription; "Trial active" can coexist with
"Guru, Subscribed".

If Semrush redirects the session check to `/multilogin/`, the CLI reports that
session confirmation is required and sends no report. If Semrush still works
in your signed-in browser, import that browser's current session again. If the
browser also shows a confirmation prompt, resolve it before importing. The CLI
never confirms a session takeover automatically. Other login redirects still
produce the expired-session error.

## Storage and lifecycle

Galleton owns the durable cookies. Every CLI process starts a transient browser context from the stored session. The MCP server reuses one context and serializes report requests. Successful reports save updated cookies back through the SDK. No plaintext cookie export or persistent Chromium profile is created by this tool.

Galleton encrypts its vault with AES-256-GCM. The local key and vault share a private state directory. This protects against accidental file disclosure, not another process running as your OS user. Its daemon API token grants access to all profiles in that daemon.

The bundled Galleton daemon includes a documented storage-only provider. It never schedules renewal or fabricates a refresh token. Semrush validates the stored session before each report. If it expires, sign in or import again. The TypeScript SDK remains unchanged. See the repository architecture document for the exact patch, tests and upstream removal criteria.

```sh
semrush auth logout
semrush daemon stop
semrush daemon start
```

Logout forgets only this CLI's Galleton profile. It does not log out your other browsers. The default daemon continues after the terminal closes; run `daemon start` after a machine reboot. No system startup service is installed automatically.

## Configuration

| Variable | Default | Purpose |
| --- | --- | --- |
| `SEMRUSH_GALLETON_URL` | `http://127.0.0.1:8771` | Existing literal-loopback Galleton API |
| `SEMRUSH_GALLETON_TOKEN_FILE` | `~/.local/share/semrush-cli/galleton/api.token` | Local API token file |
| `SEMRUSH_SESSION` | `semrush-cli` | Galleton session ID |
| `SEMRUSH_BROWSER_EXECUTABLE` | Patchright Chromium | Optional system Chromium executable |

The `setup` and `daemon` commands always manage the CLI-owned default daemon. To use another compatible Galleton instance, build it with this repository's static-provider extension and configure its `semrush` provider with the supplied adapter, set the URL and token file variables, and use the auth/report commands. Never expose the daemon API token in browser code or publish it.
