Enable SEO on a project first. Use the returned numeric `id` as `campaign_id`.
The project's `folder_id` is a different identifier.

```sh
semrush project-enable-seo --folder-id 123 --confirm
semrush audit-limits
```

Replace the example folder ID `123` with your project folder ID and campaign ID
`456` with the SEO project ID returned above. A fresh SEO project has no audit
configuration: `audit-info` returns HTTP 404 until you create one.

## Create before starting

`audit-create` creates audit settings and refuses an existing audit.
It does not launch a crawl. To replace an existing configuration, use
`audit-configure` with every option you want to retain. Omitted options use
the documented defaults. Its domain must match the project's `projectDomain`.

```sh
semrush audit-create \
  --campaign-id 456 --domain example.com \
  --page-limit 100 --dry-run

semrush audit-create \
  --campaign-id 456 --domain example.com \
  --page-limit 100 --confirm
```

Defaults: manual scheduling, email disabled, no subdomains, mobile SiteAuditBot,
website discovery, HTTPS, normal crawl delay and JavaScript rendering disabled.
Robots.txt disallow rules remain respected.

Optional settings include allow/disallow paths, removed URL parameters, excluded
checks, sitemap discovery, user agent, JavaScript rendering and crawl speed.
Use `audit-configure --help` for the full list and your plan's `audit-limits` for
allowances. JavaScript rendering can require a higher plan.

`schedule_day`: 0 manual, 1-7 Monday-Sunday, 8 daily. Selecting a recurring schedule
creates future crawl runs. `--notify` explicitly enables completion emails.

The project owns the audit name. Use `project-update --folder-id 123 --name
'Example project' --confirm` to rename it.

## Crawl a URL list

Upload a text or CSV file before selecting file discovery. This replaces the
campaign's stored URL list and requires confirmation.

```sh
semrush audit-urls-upload --campaign-id 456 --contents-file urls.txt --dry-run
semrush audit-urls-upload --campaign-id 456 --contents-file urls.txt --confirm
semrush audit-configure --campaign-id 456 --domain example.com \
  --page-limit 100 --crawl-source-type 3 --confirm
```

The returned filename is display metadata. Do not pass it as
`--crawl-source-url`. File discovery uses the list stored for that campaign.
Discovery modes are 0 website, 1 robots.txt sitemap, 2 custom sitemap URL and
3 uploaded URL list. Only custom sitemap discovery takes a sitemap URL.
Use `audit-create` instead of `audit-configure` for a fresh audit.

## Audit a site with HTTP Basic authentication

Create a password file with restricted permissions. The CLI reads its contents
and removes one final line ending. Use `-` to read the password from stdin.

```sh
semrush audit-create --campaign-id 456 --domain example.com \
  --page-limit 100 --auth-enabled true --auth-username crawler \
  --auth-password-file password.txt --confirm
```

Supply both username and password when creating or replacing credentials.
When editing an existing protected audit, include `--auth-enabled true` to
keep its current credentials, or supply both credentials to replace them.
Use `--auth-enabled false` to disable authentication. These settings edits
replace other options with their defaults unless you supply them again.
Passwords never appear in previews or returned credential fields. MCP accepts
`auth_password` directly as a write-only string.

Google Analytics and Web Bot Auth connections still require the web UI.
The CLI refuses settings replacement while either connection exists.

## Start and inspect

```sh
semrush audit-start --campaign-id 456 --dry-run
semrush audit-start --campaign-id 456 --confirm
semrush audit-status --campaign-id 456
semrush audit-info --campaign-id 456
semrush audit-snapshots --campaign-id 456
semrush audit-snapshot --campaign-id 456 --snapshot-id '<snapshot_id>'
```

Replace `<snapshot_id>` with the exact string returned by `audit-start` or
`audit-snapshots`. Keep it quoted; snapshot IDs are not campaign IDs.

Starting consumes crawl allowance and uses the saved schedule and notification
settings. Inspect `audit-info` first when using an existing campaign.

Responses retain Semrush's native JSON fields. `audit-start` returns an opaque string
`snapshot_id`; an unfinished snapshot may not have final metrics yet. Historical
snapshots and summaries are available after Semrush finishes processing.

## Inspect pages and issues

```sh
semrush audit-pages --campaign-id 456 --page 0 --limit 20
semrush audit-page --campaign-id 456 --page-id '<page_id>'
semrush audit-issue --campaign-id 456 --snapshot-id '<snapshot_id>' --issue-id 2
semrush audit-structure --campaign-id 456
semrush audit-performance --campaign-id 456
semrush audit-linking --campaign-id 456
semrush audit-history --campaign-id 456
```

Copy opaque page IDs from `audit-pages`. They change after a new crawl.
The page table starts at page 0; issue rows start at page 1. Issue IDs are the
numeric check IDs in the snapshot. `audit-recrawl --campaign-id 456 --page-id
'<page_id>' --confirm` queues a page recrawl and consumes allowance.

## Stop a running crawl

```sh
semrush audit-execution --campaign-ids '[456]'
semrush audit-abort --campaign-id 456 --confirm
```

Wait until `is_allowed_stopping` is true. Both stop commands check this flag
before writing. `audit-abort` cancels the crawl; `audit-finalize` stops collecting
pages and processes the collected results. Choose one action. A successful
response has `data:null`. Read `audit-info` until processing finishes, then use
its `current_snapshot.snapshot_id` to inspect or export the saved results.

## Download results

```sh
semrush audit-export-pages --snapshot-id '<snapshot_id>' --output pages.csv
semrush audit-export-page-issues --campaign-id 456 --output page-issues.csv
semrush audit-export-markup --snapshot-id '<snapshot_id>' --format xlsx --output markup.xlsx
semrush audit-export-issues --snapshot-id '<snapshot_id>' --format xlsx --output issues.xlsx
semrush audit-export-issue --snapshot-id '<snapshot_id>' --issue-id 2 --output broken-pages.csv
```

The CLI requires `--output` and refuses an existing file. Each export uses
Semrush's native CSV/XLSX download. See [MCP](./mcp) for retrieving downloads
from an agent.

| Web report | Command | Selected crawl |
| --- | --- | --- |
| Crawled Pages | `audit-export-pages` | Explicit snapshot ID |
| Crawled Pages with all Issues | `audit-export-page-issues` | Campaign's latest completed snapshot |
| Crawled Pages with markup | `audit-export-markup` | Explicit snapshot ID |
| Issues | `audit-export-issues` | Explicit snapshot ID |
| Pages affected by one issue | `audit-export-issue` | Snapshot and issue IDs |
| Compare Crawls | `audit-export-compare` | Two explicit snapshot IDs |

Page, page/issue matrix and markup exports accept `--relative`, `--sort` and
`--filter` with the native field values. The matrix has one column per issue;
markup exports contain structured-data fields. Use a snapshot-based export when
you need a specific historical crawl.

Crawled-links exports remain unsupported. Both native formats returned HTTP 404,
`no endpoint for the requested path`, while page exports from the same snapshot
succeeded. This is an endpoint failure, not evidence of a Guru plan restriction.
The All reports batch download is not yet exposed.

## Compare two crawls

Use `audit-snapshots` to choose two different completed snapshots from the same
campaign. The web UI defaults the first selection to the previous crawl and the
second to the latest crawl.

```sh
semrush audit-export-compare \
  --first-snapshot-id '<previous_snapshot_id>' \
  --second-snapshot-id '<latest_snapshot_id>' \
  --output comparison.csv
```

Use `--format xlsx --output comparison.xlsx` for Excel. Both snapshot IDs are
required. The CLI preserves your selection order and Semrush's native file.
Its columns put the second crawl before the first, followed by provider-computed
deltas. The CLI does not reorder columns or recalculate changes. This download
leaves campaign settings and crawl allowance unchanged.

Use the web UI for connected integrations.
Deleting a project also deletes its attached audit.

## Request evidence

The configuration and launch contracts come from the current
[Site Audit wizard](https://static.semrush.com/siteaudit/index/6543.8fd07665f4ecb251ca39.js),
[settings module](https://static.semrush.com/siteaudit/index/5444.c73f5f9232917b1e67fc.js)
and [API client](https://static.semrush.com/siteaudit/index/910.743a405979e048d96c5e.js).
A disposable account project verified configuration, launch, status and snapshot
reads with manual scheduling, email disabled and a 10-page cap. Live checks also
verified page/issue details, page recrawling, abort, finalize, the saved finalized
snapshot and native CSV/XLSX exports.

The protected-audit pass uploaded a one-URL list through both the native UI and
the CLI/MCP request. A ten-page cap finished at six pages, including HTTP 200
for the protected HTML page. Credential creation, replacement, retention and
explicit disabling passed readbacks. The owned projects were deleted afterward.

The comparison download and default snapshot order follow the current
[native export module](https://static.semrush.com/siteaudit/review/3909.2dd2f158589125911115.js).
Both formats passed native, CLI and MCP checks on two existing completed
23-page crawls. The checks left their settings and saved results intact.
